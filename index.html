Search rules (V3.10): - Normalise both sides: lowercase, diacritics removed (õ→o, ü→u), punctuation/brackets/arrows removed. `pork` finds `Põrk`. - Every query word must match some name word (any order): exact > prefix > substring (≥3 chars) > typo (Levenshtein ≤1 for 4–6 chars, ≤2 for ≥7). `Juhan Seebeg` finds `Juhan (Ivan) Seeberg`. - Alternative names in brackets/after ← are searchable: `ivan seeberg` finds `Juhan (Ivan) Seeberg`. - A 3–4 digit word matches birth/death year: `Juhan 1871`. - No result cap. No collapse, no expand marker. Focal person's descendants rendered immediately, all generations. 4. Missing parent → nothing shown above that person. No placeholder text, no ⧉. Father unknown, mother known → default line = mother's (father simply absent). 5. Click on mother (shown as father's `+` spouse line) → ⧉ swap (§7). 6. Value: show everything known about the focal person at once (ancestors + descendants). Overload prevented by: one ancestor line at a time (⧉), other branches collapsed (↳). 9. User scrolls horizontally to explore time. Vertically to explore generations. 10. Hover on a bar → instant simple tooltip (name + lived years, §7). Full data → profile panel (§7). 11. GEDCOM parser (browser, JavaScript) ### 3.1 Required fields | Record | Tags to parse | |--------|--------------| | INDI | NAME, SEX, BIRT/DATE, BIRT/PLAC, DEAT/DATE, DEAT/PLAC, NOTE, FAMC, FAMS | | FAM | HUSB, WIFE, CHIL, MARR/DATE | ### 3.2 Date handling | Input | Treatment | |-------|-----------| | `DD MMM YYYY` | Exact date → year extracted | | `MMM YYYY` | Exact year | | `YYYY` | Exact year | | `ABT YYYY` | Approximate → `approx=true` | | `BEF YYYY` / `AFT YYYY` | Approximate → `approx=true` | | Range (e.g. two dates) | Use earlier year, `approx=true` | | Missing | `null` | ### 3.3 Encoding - UTF-8: pass through. - ANSEL: convert to UTF-8 before parsing. - Non-Latin scripts (Cyrillic, Hebrew, Arabic, Japanese, CJK): must display without garbling. No transliteration. ### 3.4 Edge cases - Multiple marriages per individual: select the FAM record whose CHIL list contains the focal descendant. - Individual appears in multiple families: use FAMC for parent family, FAMS for own marriage families. - Missing dates: render as placeholder (no bar, estimated position — §5.5). - Malformed records: skip silently, continue parsing. - Large files (500+ INDI): parse asynchronously with progress indicator. Do not block UI. ### 3.5 Reference dataset `export-BloodTree.ged` — 968 individuals, 366 families. Estonian names with diacritics (ä, ö, ü, õ). Multi-marriage scenarios. Use for all testing. --- ## 4. Timeline rendering ### 4.1 Scale (DO NOT CHANGE without recalibrating all data) ``` X0 = 247.6 # x-position of YEAR0 YEAR0 = 1680 PX_PER_YEAR = 3.765 # 75.3px per 20 years TODAY_YEAR = float # fractional year of current date, e.g. 2026.471 TODAY_X = X0 + (TODAY_YEAR - YEAR0) * PX_PER_YEAR # ~1552.1 for June 2026 year_to_x(y) = X0 + (y - YEAR0) * PX_PER_YEAR ``` ### 4.2 Layout constants ``` BAND_X = 20 BAND_W = TODAY_X - BAND_X # hard stop at today BAND_PAD_TOP = 22 # V4.0 BAND_PAD_BOTTOM = 22 BAND_GAP = 64 # holds the generation header (V4.2) ROW_H = 25 # sibling row pitch (V4.0, larger type) SIB_BAR_H = 10 SIB_BAR_W = 90 # default sibling bar width (used only for gradient/fade bars) ANCESTOR_BAR_H = 14 # heir bar (V4.2); connectors use this height ANCESTOR_BAR_Y_OFFSET = 4 # bar top = row_y + 4 ANCESTOR_ROW_PITCH = 58 # V4.2 SPOUSE_STEP = 20 # pitch between several spouse lines ANCESTOR_TEXT_X_PAD = 16 # gap between birth x and name right-edge (birth node needs room, V4.2) MIN_LABEL_X = 200 # no label right-edge left of x=200 (gen-label rail protection) MIN_ANCESTOR_BAR_W = 24 ``` ### 4.3 Axis ``` axis_start = 1680 axis_end = floor(TODAY_YEAR / 20) * 20 # e.g. 2020 for any date in 2020–2039 axis_years = range(axis_start, axis_end + 1, 20) ``` Both top ruler and bottom axis use the same `axis_years` list. No horizontal axis rules (removed V3.12). Grid lines run from just below the top year labels to just above the bottom year labels, so every line ends at its year. Top ruler: `position: sticky; top: 0` — native CSS, no JS sync. Timeline view (V5.25): the page does not scroll; the timeline area is its own scroll container (height = viewport − header, overflow both ways, like a spreadsheet), so the ruler stays visible when scrolling down AND sideways. Ruler background = page background, slightly translucent with blur. - Century years (1700, 1800, 1900, 2000): bold label, stronger grid line. Every other century (1700–1799, 1900–1999) has a faint background stripe. - Today: dashed vertical line at `TODAY_X` (Sunset, §6.3) + pill `Today` right of the line on both rulers. Pill text sits on the same baseline as the year labels. - Year digits: tabular figures. Zero is drawn open (no slash, V4.17). ### 4.4 SVG paint order (strict) Layer 1 → band backgrounds + focal-row highlight (painted first = bottom) Layer 2 → grid lines + connectors Layer 3 → bars + text (painted last = always on top) **Grid lines must never visually cross bars. Enforced by document order.** --- ## 5. Bar rules ### 5.1 Ancestor bar - Name + years: `text-anchor="end"`, x = `x_birth − ANCESTOR_TEXT_X_PAD`, clamped so x ≥ MIN_LABEL_X. - Spouse line: same x, `text-anchor="end"`, y = `bar_y + 33` (+ `SPOUSE_STEP` per further spouse). No bar for spouse. - Label format (2026-10-03): ``` Line 1: Firstname Lastname (1869–1890) · Kurla Line 2: +Spouse Name (1871–1895) · Kurla ⧉ ``` - V5.35: separator = middle dot `·` (U+00B7) with 2× NBSP each side; only the dot is grey (`--header-sub`), place keeps the name colour, weight 400. Place = first part of PLAC before the first comma (`Lübeck`, not `Lübeck, Germany`); full place in the profile panel. A grey place (V5.34) did not separate enough and hurt readability. - Applies to all rows: ancestors, `+partner`, siblings, children (`labelHtml()`). - Years in parentheses, en dash `–`. Unknown death → `(1685–?)`. Unknown birth → `?`. Estimated birth range keeps `b. {lo}–{hi}` (§5.4). - `+` prefix marks the spouse/partner line. Spouse never gets a bar (avoids reading as a sibling). - Missing birthplace → omit ` · place` entirely. - Longer labels → more labels hit MIN_LABEL_X clamp. Verify with real data. - Name baseline: `bar_y + 12` (vertically centred on the 14px bar). Name + years bold, place regular weight (V5.17). - Bar y: `row_y + ANCESTOR_BAR_Y_OFFSET`. Bar fully rounded (radius = height / 2). - Birth node (V4.2): circle r=6 at `(x_birth, bar centre)`, bar colour, 3px ring in band colour. Heir/focal bars only. - Focal row (V4.2, V4.14): light tint in the focal's sex colour (`--focal-tint-m/f`), rounded at both ends, spanning the band. No coloured edge line. ### 5.2 Sibling bar - Label format: `Name (1823–1880) · place ↳` (same as ancestors, §5.1). - Name + years: `text-anchor="end"`, x = `x_birth − 6`, clamped so x ≥ MIN_LABEL_X. - Bar y: `row_y`. ### 5.2b Birth ticks (V3.4) - No solid tick on normal bars — the bar's left edge marks birth (heir bars: birth node, §5.1). - Dashed tick only when there is no bar: estimated birth (unknown year) and birth-range midpoint. ### 5.3 Bar width rules | Condition | Bar width | |-----------|-----------| | Exact birth + exact death | `year_to_x(death) − year_to_x(birth)` — mathematically exact | | Living (in ALIVE set) | Solid: `today_x − x_birth`. Then gradient fade. Total width capped at `today_x − x_birth + tail`, never exceeds `today_x` | | Unknown death, not living | Solid: `year_to_x(last_child_birth_in_next_gen) − x_birth`. Then gradient fade. Capped at `today_x` | | Approximate death only | Solid bar; width based on approximate year; no tooltip | All gradient bars: `total_w = min(solid_w + 130, TODAY_X − x_birth)`. Hard cap. No bar extends past `TODAY_X`. ### 5.4 Estimated birth-year range (V5.29) Applied when data is a range, not a year (`BET 1688 AND 1692`, or "1688-1692"). - Render: a normal life bar, treated as `BET` (§5.4b): fades in from lo to hi, then the usual rules — exact/qualified death sets the end; unknown death → solid at least through the children's births and the last marriage, then haze. - Label: `1688/92` like other BET dates, e.g. `(1688/92–>1751)`. - Replaces the old dashed-outline box (V3), which showed no lifespan. ### 5.4b Date qualifiers (GEDCOM: exact, ABT/CAL/EST = circa, BEF, AFT, BET…AND; V5.17) | Qualifier | Bar start (birth) | Bar end (death) | Label | |---|---|---|---| | Exact | hard | hard | `1837` | | Circa | soft ±3 y | soft ±3 y | `~1837` | | Before X | fades in over 10 y up to X | fades out over 10 y, gone at X | `<1837` | | After X | fades in from X over 10 y | solid to X, fades out over 20 y | `>1837` | | Between X–Y | fades in X→Y | solid to X, fades out to Y | `1830/37` | - Tooltip age (V5.18), shown on every bar with a known birth year. Latest life event = max of the person's own dated events (except birth/death/burial), children's births, marriages. | Death | Tooltip | |---|---| | exact | `lived N years` (`about` if birth is approximate) | | circa | `lived about N years` | | before X | `lived {min}–{X−b} years` (min from latest event) or `lived under {X−b} years` | | after X | `lived at least {X−b} years` | | between X–Y | `lived {X−b}–{Y−b} years` | | unknown, not living | `lived at least {latest event − b} years`; nothing if no later event | | living | `age N` | - Unknown death but married: bar stays solid at least until the (last) marriage year, hazes out after (a person must never look dead before their wedding). - Birth qualifier applies also when the death is unknown (V5.29): the bar start softens (circa ±3 y, before/after/between fade in); before V5.29 it started hard in that case. - Unknown birth + known death: hazes in from the estimate (line child's birth − 18, else parent + 18) over 10 y, solid to death; death qualifier sets the end. ### 5.5 Unknown birth year (Q29, V4.15–V4.16) Applies in every generation band (ancestors' siblings and descendants). - Estimated year = birth year of the later-born parent + 18. Parent without a year → that parent's own estimate (recursive, depth ≤ 12). - No parents in the data → general estimate (children's birth − 28 / siblings' mean). - Order: persons with a known birth year first (existing order), then persons without, ordered by estimate, then by GEDCOM family order, then name — never by who is focal (V5.12 fix: clicking an unknown-year sibling made them jump to the top of the unknown group). - Exception: focal's children grouped under a partner header (§7) → unknown-year children go to the end of their own partner group. - Render (V5.12): unknown birth AND death → hazy bar like unknown-dated ancestors: hazes in from the estimated birth over 10 years, solid up to the first child's birth (or estimated birth + 18 if no children), hazes out over 20 years. Sibling colours for siblings/descendants, primary for heir/focal. Unknown birth but known death → dashed tick at the estimated x, no bar. Label `(?–?)`. Connectors use the estimated x. --- ## 6.
